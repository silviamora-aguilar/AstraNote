AstraNotes Course Artifact Guide

SDLC document map for everything created so far

This page groups the generated class documents by the software development life cycle so students can stop hunting through file names and instead read artifacts in the order they support the project.

Recommended reading flow: Vision -> Requirements -> Design -> Planning -> Testing -> Acceptance

How to use this page

Each phase below answers a different SDLC question. Open only the documents needed for that phase instead of scanning the full workspace every time.

1. VisionWhy are we building AstraNotes?
2. RequirementsWhat must the system do?
3. DesignHow should the solution work?
4. PlanningWhat will we do next and when?
5. VerificationHow will we test and measure done?
6. AcceptanceHow do we close and sign off?

What is covered so far

Web multi-user planning baseline is synchronized across requirements, user stories, backlog, traceability, tests, sprint plans, release gates, and customer acceptance.

  • Decision lock complete: FastAPI, Jinja2 + HTMX, SQLite (PostgreSQL-ready), server-side sessions + CSRF.
  • Requirement baseline aligned to 91 tracked items: REQ, NFR, SRG, SMR, and WEB.
  • BL-22 added and propagated through planning, testing, and release governance artifacts.
  • Acceptance package now includes explicit web multi-user sign-off criteria.
